# Лабораторная работа №2. Метрика Джилба

Расчёт метрики Джилба для программы на языке **Go** с помощью парсера на **C#**
(Windows Forms). Метрики считаются по **абстрактному синтаксическому дереву**
(AST) программы.

## Состав работы

| Каталог/файл | Назначение |
|---|---|
| `go/analyzed_program.go` | Анализируемая программа на Go. Содержит **все** операторы цикла и ветвления языка, включая оператор множественного выбора. |
| `parser/` | Парсер языка Go и расчёт метрик на C# (WinForms). |
| `parser/GoLexer.cs` | Лексический анализатор Go (токенизация, комментарии, литералы). |
| `parser/GoAst.cs` | Узлы AST и рекурсивный парсер Go. |
| `parser/GoAnalyzer.cs` | Обход AST и расчёт метрик CL, cl, CLI. |
| `parser/GoAstPrinter.cs` | Отладочный вывод AST в виде дерева. |
| `parser/MainForm.cs` | Графический интерфейс. |
| `parser/LineNumberStrip.cs` | Полоса с номерами строк для области кода. |
| `parser/Program.cs` | Точка входа. |
| `GilbMetricParser.slnx` | Решение Visual Studio / `dotnet`. |

## Что содержит анализируемая Go-программа

Единственное ключевое слово цикла в Go — `for`, но у него есть четыре формы.
В программе присутствуют все они:

1. `for { … }` — бесконечный цикл;
2. `for cond { … }` — цикл с одним условием (аналог `while`);
3. `for init; cond; post { … }` — классический цикл;
4. `for k, v := range coll { … }` — цикл по коллекции (`range`).

Ветвления:

1. `if … { }`
2. `if … { } else { }`
3. `if … { } else if … { } else { }`
4. `switch expr { case …: … default: … }` — с `fallthrough`;
5. `switch { case cond: … }` — switch без выражения;
6. `switch v := x.(type) { case T: … }` — type switch;
7. `select { case …: … default: … }` — множественный выбор по каналам.

Дополнительно использованы `break` и `continue` (в том числе помеченный
`break loop`).

## Определения метрики (по методичке)

* **CL** — абсолютная сложность: количество условных операторов.
  Условными считаются операторы ветвления (`if` / `else if`) **и циклы**
  (`for` во всех формах).
* **cl** — относительная сложность: `CL / общее число операторов программы`.
* **CLI** — максимальный уровень вложенности условного оператора
  (циклы `for` также учитываются при вычислении уровня).

Оператор множественного выбора (`switch`/`select`/type switch): каждая ветвь
`case` является условием и даёт **+1 к CL**; ветвь `default` — аналог `else`
и в CL не входит. Оператор эквивалентен цепочке из числа `case`-ветвей
условных операторов `if / else if`, поэтому его вклад в CLI равен
`уровень + число case`. Для `switch` с ветвью `default` это совпадает с
формулой методички `n − 1` / `n − 2` (где `n` — число ветвей `case` + `default`).

Уровень вложенности считается по количеству охватывающих тел управляющих
конструкций (`if`, `for`, `switch`, `select`); тело функции уровень не
увеличивает. Ветви условного оператора также наращивают уровень:

* тело `if` — на один уровень;
* ветвь `else { … }` — на один уровень (вложенный `if` внутри `else`
  получает уровень больше, чем сам `if`);
* ветвь `else if …` — на один уровень (цепочка `if / else if / else if`
  наращивает вложенность подобно ветвям `switch`).

## Результат для демонстрационной программы

```
CL  (абсолютная сложность)       = 33
cl  (относительная сложность)    = 0,4459
CLI (максимальный уровень влож.) = 4
Всего операторов программы       = 74
```

Основные источники CL:

| Конструкция | Вклад в CL |
|---|---|
| Одиночные `if` / `else if` | 1 каждый |
| Циклы `for` (все формы) | 1 каждый (7 циклов) |
| `switch` без выражения (4 ветви) | 3 |
| `switch` по выражению (4 ветви) | 3 |
| type switch (4 ветви) | 3 |
| `select` (2 ветви) | 1 |

Максимальный уровень вложенности CLI = 4 достигается на вложенном `if`
внутри ветви `else` (строки 37–42): `for` → `if` → `else if` → `else { if … }`.

## Сборка и запуск

Требуется .NET SDK (Windows). Проект нацелен на `net9.0-windows`, при
необходимости автоматически запускается на более новом установленном рантайме
(`RollForward=LatestMajor`).

```powershell
cd parser
dotnet build -c Release
dotnet run -c Release
```

Готовый файл:
`parser/bin/Release/net9.0-windows10.0.26100.0/GilbMetricParser.exe`.

### Графический интерфейс

* **Файл → Открыть программу на Go…** — выбрать `.go`-файл.
* **Файл → Загрузить демонстрационный пример** — открыть `analyzed_program.go`.
* **Анализ → Выполнить расчёт метрики** — посчитать метрику.
* **Анализ → Показать AST (отладка)** — открыть окно с текстовым
  представлением построенного синтаксического дерева (для проверки разбора).
* Слева отображается исходный код **с полосой номеров строк**, справа —
  значения CL, cl, CLI, общее число операторов и таблица найденных конструкций
  (тип, строка, уровень, вклад в CL).
* Выбор строки в таблице подсвечивает соответствующий оператор в коде.

## Алгоритм парсера

1. **Лексический анализ** (`GoLexer`): исходный текст разбивается на токены;
   удаляются комментарии, распознаются строковые/символьные литералы, числа,
   операторы и ключевые слова.
2. **Синтаксический анализ** (`GoAst`): рекурсивный спуск строит AST.
   Разбираются объявления верхнего уровня, функции и методы, блоки и операторы
   (`if`/`for`/`switch`/`select`/`return`/`break`/`continue`/`goto`/метки).
   Границы операторов определяются по правилу автоматической вставки `;`
   (ASI), а тело управляющей конструкции — по первой `{` на верхнем уровне
   скобок. Составные литералы в заголовках (`[]T{…}`, `map[K]V{…}`) и
   индексные выражения (`a[i]`) распознаются и не путаются с телом блока.
   Для `switch`/`select` разбираются все ветви `case`/`default`, определяется
   type switch (`.(type)`) и `range` в цикле.
3. **Обход AST** (`GoAnalyzer`): вычисляются CL (число условных операторов —
   `if`/`else if`, циклы `for` и ветви `case` операторов `switch`/`select`),
   CLI (максимальный уровень вложенности) и общее число операторов (количество
   узлов-операторов, включая `else if`).
4. **Отладка** (`GoAstPrinter`): строит текстовое представление AST
   (доступно через пункт меню «Показать AST»).

### Ограничения

Не разбираются тела анонимных функций (функциональных литералов), если они
встречаются внутри выражений — управляющие конструкции в них не учитываются.
Для демонстрационной программы результат корректен.
