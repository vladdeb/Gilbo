# Лабораторная работа №2. Метрика Джилба

Расчёт метрики Джилба для программы на языке **Go** с помощью парсера на **C#**
(Windows Forms).

## Состав работы

| Каталог/файл | Назначение |
|---|---|
| `go/analyzed_program.go` | Анализируемая программа на Go. Содержит **все** операторы цикла и ветвления языка, включая оператор множественного выбора. |
| `parser/` | Парсер языка Go и расчёт метрик на C# (WinForms, .NET 10). |
| `parser/GoLexer.cs` | Лексический анализатор Go (токенизация, комментарии, литералы). |
| `parser/GoAnalyzer.cs` | Структурный анализ и расчёт метрик CL, cl, CLI. |
| `parser/MainForm.cs` | Графический интерфейс. |
| `parser/Program.cs` | Точка входа; поддерживает GUI и консольный режим `--cli`. |
| `GilbMetricParser.slnx` | Решение Visual Studio / `dotnet`. |

## Что содержит анализируемая Go-программа

Единственное ключевое слово цикла в Go — `for`, но у него есть четыре формы.
В программе присутствуют все они:

1. `for { … }` — бесконечный цикл;
2. `for cond { … }` — цикл с одним условием (аналог `while`);
3. `for init; cond; post { … }` — классический цикл;
4. `for k, v := range coll { … }` — цикл по коллекции (`range`).

Ветвления:

1. `if … { }`
2. `if … { } else { }`
3. `if … { } else if … { } else { }`
4. `switch expr { case …: … default: … }` — с `fallthrough`;
5. `switch { case cond: … }` — switch без выражения;
6. `switch v := x.(type) { case T: … }` — type switch;
7. `select { case …: … default: … }` — множественный выбор по каналам.

Дополнительно использованы `break` и `continue` (в том числе помеченный
`break loop`).

## Определения метрики (по методичке)

* **CL** — абсолютная сложность: количество условных операторов
  IF–THEN–ELSE.
* **cl** — относительная сложность: `CL / общее число операторов программы`.
* **CLI** — максимальный уровень вложенности условного оператора.

Оператор множественного выбора (`switch`/`select`/type switch) с **n**
ветвями эквивалентен **n − 1** условным операторам IF–THEN–ELSE с
эквивалентной вложенностью **n − 2**.

Уровень вложенности в реализации считается по количеству охватывающих тел
управляющих конструкций (`if`, `for`, `switch`, `select`); тело функции
уровень не увеличивает.

Ветви условного оператора также наращивают уровень:

* тело `if` — на один уровень;
* ветвь `else { … }` — на один уровень (поэтому вложенный `if` внутри `else`
  получает уровень больше, чем сам `if`);
* ветвь `else if …` — на один уровень (цепочка `if / else if / else if`
  наращивает вложенность подобно ветвям `switch`).

## Результат для демонстрационной программы

```
CL  (абсолютная сложность)       = 26
cl  (относительная сложность)    = 0,3562
CLI (максимальный уровень влож.) = 4
Всего операторов программы       = 73
```

Основные источники CL:

| Конструкция | Вклад в CL |
|---|---|
| Одиночные `if` / `else if` | 1 каждый |
| `switch` без выражения (4 ветви) | 3 |
| `switch` по выражению (4 ветви) | 3 |
| type switch (4 ветви) | 3 |
| `select` (2 ветви) | 1 |

Максимальный уровень вложенности CLI = 4 достигается на вложенном `if`
внутри ветви `else` (строки 37–42): `for` → `if` → `else if` → `else { if … }`.


## Сборка и запуск

Требуется .NET SDK (Windows). Проект нацелен на `net9.0-windows`, при
необходимости автоматически запускается на более новом установленном рантайме
(`RollForward=LatestMajor`).

```powershell
cd parser
dotnet build -c Release
dotnet run -c Release
```

Готовый файл:
`parser/bin/Release/net9.0-windows10.0.26100.0/GilbMetricParser.exe`.

### Графический интерфейс

* **Файл → Открыть программу на Go…** — выбрать `.go`-файл.
* **Файл → Загрузить демонстрационный пример** — открыть `analyzed_program.go`.
* **Анализ → Выполнить расчёт метрики** — посчитать метрику.
* Слева отображается исходный код **с полосой номеров строк**, справа —
  значения CL, cl, CLI, общее число операторов и таблица найденных конструкций
  (тип, строка, уровень, вклад в CL).
* Выбор строки в таблице подсвечивает соответствующий оператор в коде.

## Алгоритм парсера

1. **Лексический анализ** (`GoLexer`): исходный текст разбивается на токены;
   удаляются комментарии, распознаются строковые/символьные литералы, числа,
   операторы и ключевые слова.
2. **Структурный анализ** (`GoAnalyzer`): однопроходный обход токенов со стеком
   контекстов фигурных скобок и стеком цепочек ветвлений. Определяются тела
   управляющих конструкций, вычисляется текущая глубина вложенности. Для
   `switch`/`select`/type switch подсчитывается число ветвей (`case` + `default`),
   после чего вклад в CL равен `n − 1`, а эквивалентный уровень — `n − 2`
   (в соответствии с методикой). Цепочка `if / else if / … / else` отслеживается
   отдельным стеком: каждая очередная ветвь `else` увеличивает уровень
   вложенности на единицу и цепочка автоматически закрывается, когда после
   очередного тела не следует `else`.
3. **Подсчёт операторов**: по началам операторов (первый значимый токен строки
   с учётом переносов внутри скобок и продолжений выражений).

### Ограничения

Парсер ориентирован на корректно отформатированный код (стиль `gofmt`) и не
является полным грамматическим разбором Go. Возможны неточности при
использовании составных литералов непосредственно в заголовке `if`/`for`/`switch`.
Для демонстрационной программы результат корректен.
